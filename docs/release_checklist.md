# 上线前验收清单

本文用于轻量化上线前的人工验收。自动化测试负责基础契约，本文负责覆盖真实设备、麦克风、SoundFont 下载和交互路径。

## 1. 使用范围

适用于每次准备发布或交付试用版前的最后一轮检查。

不替代以下自动化质量门禁：

```bash
flutter analyze
flutter test
```

## 2. 验收前准备

- [ ] 使用干净工作区或确认待验收改动已经提交
- [ ] 已运行 `flutter pub get`
- [ ] 已运行 `flutter analyze`
- [ ] 已运行 `flutter test`
- [ ] iOS 验收前已运行 `cd ios && pod install`
- [ ] 至少准备一台真机或可用模拟器；跟随模式必须使用真机复测麦克风
- [ ] 准备一份可导入的 MIDI 文件，优先使用包含多轨道和休止段的曲目

## 4. 手动验收项目

### 4.1 首次启动 SoundFont 下载

目的：确认首次运行时音色库准备流程可用，失败时用户知道如何恢复。

- [ ] 清理应用数据或使用首次安装状态启动 App
- [ ] 保持网络可用，启动后观察 SoundFont 状态
- [ ] 首页或播放器页应展示检查中 / 下载中 / 已就绪等状态
- [ ] 下载完成后状态应变为音色已就绪
- [ ] 如网络不可用或下载失败，应出现失败提示和重试入口
- [ ] 点击重试后不会崩溃，状态能重新进入准备流程

通过标准：音色准备成功后可以播放 MIDI；失败路径有明确提示和重试入口。

### 4.2 导入 MIDI

目的：确认用户能从文件系统导入标准 MIDI 文件。

- [ ] 点击首页「导入 MIDI 乐谱」
- [ ] 选择一份有效 MIDI 文件
- [ ] 导入完成后自动进入播放器页面
- [ ] 播放器标题应显示当前曲目名称
- [ ] 轨道列表应显示可控制轨道
- [ ] 导入异常文件时应显示解析失败提示，而不是崩溃

通过标准：有效文件能进入播放器，无效文件有错误提示。

### 4.3 播放 / 暂停 / seek

目的：确认基础播放控制可用，seek 后没有残留长音。

- [ ] 点击播放，当前时间和进度条开始推进
- [ ] 点击暂停，播放停止推进且没有持续长音
- [ ] 再次播放能从暂停位置继续
- [ ] 拖动进度条或使用快进 / 后退按钮进行 seek
- [ ] seek 后播放位置正确更新
- [ ] seek 前后的活动音符应被清理，不应出现卡音或残留长音

通过标准：播放控制稳定，seek 后声音状态正确。

### 4.4 设置页调整默认速度

目的：确认轻量设置页能影响实际播放默认值。

- [ ] 从首页或播放器页右上角进入「设置」
- [ ] 调整「默认速度」滑块
- [ ] 点击「应用到当前曲目」后，当前播放器速度应更新
- [ ] 重新导入一首 MIDI，新曲目应使用设置中的默认速度
- [ ] 点击「恢复默认」后，默认速度回到推荐值

通过标准：设置值能被保存、应用，并影响新导入曲目的初始速度。

### 4.5 跟随模式打开 / 关闭

目的：确认跟随模式生命周期完整，打开和关闭都能释放资源并恢复播放速度。

- [ ] 导入 MIDI 并进入播放器
- [ ] 在轨道列表选择主旋律轨道
- [ ] 打开「跟随模式」开关
- [ ] App 应请求或使用麦克风权限
- [ ] 跟随状态应进入实时跟随或等待起拍
- [ ] 关闭「跟随模式」开关
- [ ] 播放速度应恢复到 1.0x 或当前手动设置值，不应继续被跟随逻辑改写
- [ ] 多次打开 / 关闭不应崩溃

通过标准：跟随模式可重复进入和退出，资源释放正常。

### 4.6 麦克风权限拒绝 / 授权

目的：确认权限边界有清晰反馈。

- [ ] 首次打开跟随模式时拒绝麦克风权限
- [ ] App 应展示需要麦克风权限的说明
- [ ] 拒绝后跟随模式不应进入活动状态
- [ ] 在系统设置中重新授权麦克风
- [ ] 回到 App 后再次打开跟随模式
- [ ] 跟随模式应能正常启动麦克风输入

通过标准：拒绝权限时不崩溃、不假装开启；授权后能正常启动。

### 4.7 长休止等待恢复

目的：确认跟随模式遇到长休止时能暂停等待，并在下一次起拍后恢复。

- [ ] 使用包含明显长休止的 MIDI 曲目
- [ ] 选择包含休止后的主旋律轨道
- [ ] 打开跟随模式并开始播放 / 演奏
- [ ] 当谱面进入长休止区间时，状态应进入等待起拍
- [ ] 伴奏应暂停或停止推进，不应在休止后自动抢跑
- [ ] 演奏下一个正确起拍音后，状态应恢复实时跟随
- [ ] 伴奏应继续播放并根据演奏速度调整

通过标准：长休止期间等待用户输入，下一次有效 onset 后恢复播放。
